# Phase 0 — Monorepo Restructure Design

**Date:** 2026-05-14
**Status:** Approved (pending user review of this spec)
**Source plan:** `BRAIN_PHASED_PLAN.md` Phase 0
**Branch:** `phase-0-monorepo` (off `main`)
**Merge style:** Single PR, squash-merge, with discrete commits for reviewability

---

## Summary

Reshape the Looqus repo from a flat Next.js layout into the Brain monorepo skeleton, **without scaffolding any service shells, Python tooling, or infra/proto code yet**. The Next.js app keeps running identically; only its location and the surrounding workspace tooling change.

This is a deliberate scope reduction from the original Phase 0 in `BRAIN_PHASED_PLAN.md`, which would have scaffolded all 6 service shells + 8 packages + 6 pylibs + Docker Compose + 3-language CI. Service shells and shared packages will be added when their owning phases begin (e.g., `apps/ingestion-service/` scaffolds at the start of Phase 2). Rationale: scaffolding services weeks before they're implemented produces dead code that rots — proto stubs go stale, Dockerfiles target outdated package versions, generated clients drift from contracts.

---

## Decisions log

| # | Decision | Choice | Reasoning |
|---|---|---|---|
| Q1 | Phase 0 scope | **Minimal** — frontend move + monorepo tooling + placeholder dirs only | Avoid dead scaffolding; defer service shells to their phases |
| Q2 | Package manager | **pnpm + Turborepo** (replaces npm) | Cheapest moment to switch is now (one workspace); matches plan |
| Q3 | `.env` handling | Move all `.env*` files into `apps/frontend/`; no deploy config to update | Not deployed yet; AWS later (Phase 11+) |
| Q4 | Branch strategy | **Single branch, discrete commits, squash-merge** | Reviewable history without leaving `main` broken |
| Q5 | CI scope | **TS-only minimal job** (`pnpm install`, `pnpm turbo run typecheck build`) | No Python/proto code yet to lint; add when relevant |

## Section 1 — In/out scope

### In scope
- `git mv` everything currently at repo root that belongs to the Next.js app → `apps/frontend/`
- pnpm workspace at root (replaces npm + `package-lock.json`)
- Turborepo at root (`turbo.json`)
- Top-level placeholder directories with one-paragraph READMEs: `apps/`, `packages/`, `pylibs/`, `protos/`, `infra/`, `tools/`, `docs/`
- Minimal TS-only CI workflow (`pnpm install`, `pnpm turbo run typecheck build`)
- `tsconfig.base.json` at root; `apps/frontend/tsconfig.json` extends it
- `.npmrc` with hoisting hints for shadcn/Radix/Tailwind compatibility
- Phase 0 progress notes in `BRAIN_PHASED_PLAN.md`

### Out of scope (deferred to later phases)
- Service shells: `apps/api-gateway/`, `apps/core-service/`, `apps/ingestion-service/`, `apps/analytics-service/`, `apps/intelligence-service/`, `apps/notifications-service/`
- All real `packages/*` (`ui`, `lib-metrics`, `lib-regional`, `lib-grpc-clients`, `lib-kafka`, `lib-auth`, `eslint-config`, `tsconfig`)
- All `pylibs/*`
- Protobuf scaffolding, `buf` config, `tools/codegen-proto.sh`
- Docker Compose (`infra/docker-compose.yaml`)
- Python tooling (`pyproject.toml`, uv, ruff, mypy, pytest)
- `infra/` CDK stacks
- Root `Makefile`, `make dev`

### Stays at repo root, unchanged
- `CLAUDE.md`, `AI_INSIGHTS_PLAN.md`, `BRAIN_PHASED_PLAN.md`, `README.md`
- `.git/`, `.gitignore`, `.claude/`
- `.github/workflows/sync-ads-cron.yml` (only curls a deployed URL — path-independent)

## Section 2 — File-by-file move map

### Move into `apps/frontend/`

Directories (preserving contents):
```
app/         components/   constants/   docs/    hooks/
lib/         module/       prisma/      public/  scripts/  stores/
```

Files:
```
components.json        eslint.config.mjs    next-env.d.ts    next.config.ts
package.json           postcss.config.mjs   proxy.ts         shopify.app.toml
tsconfig.json          .env*  (every dotfile matching the pattern)
```

`apps/frontend/tsconfig.json` is then edited to add `"extends": "../../tsconfig.base.json"`.

`apps/frontend/package.json` keeps its current `name` (`shopify-analitcs`) — renaming is a Phase 1+ concern when other workspaces start importing from it.

### New files at repo root

```
package.json               # private workspace root, name: "brain-monorepo"
pnpm-workspace.yaml        # declares apps/* and packages/*
turbo.json                 # pipeline: build, typecheck, lint, dev
tsconfig.base.json         # strict TS settings shared
.npmrc                     # public-hoist-pattern for shadcn/Radix/Tailwind

apps/README.md
packages/README.md
pylibs/README.md
protos/README.md
infra/README.md
tools/README.md
docs/README.md
```

Each placeholder README is one paragraph naming the directory's eventual purpose and the phase that begins populating it.

### Delete

```
node_modules/         # regenerated by pnpm install
package-lock.json     # replaced by pnpm-lock.yaml at root
```

## Section 3 — Commit sequence

Five commits on `phase-0-monorepo`, squash-merged to `main`:

1. **`chore: relocate Looqus Next.js app into apps/frontend/`** — pure `git mv`. No content edits. App is technically broken at this point because root has no workspace config; the next commit fixes that.
2. **`chore: add pnpm workspace + Turborepo + tsconfig.base`** — root `package.json`, `pnpm-workspace.yaml`, `turbo.json`, `tsconfig.base.json`, `.npmrc`. Edit `apps/frontend/tsconfig.json` to extend the base. After this commit, `pnpm install` works and the frontend builds.
3. **`chore: scaffold top-level placeholder dirs`** — seven READMEs in `apps/`, `packages/`, `pylibs/`, `protos/`, `infra/`, `tools/`, `docs/`.
4. **`ci: add TS-only build/typecheck workflow`** — `.github/workflows/ci.yml` running `pnpm install` then `pnpm turbo run typecheck build` on PR + push to main.
5. **`docs: mark Phase 0 done in BRAIN_PHASED_PLAN.md`** — check off completed items, add a "Deviation note" callout: scope reduced to frontend move only per Q1=B; service shells deferred to their phases.

## Section 4 — Verification plan (non-disruption guarantee)

Before opening the PR, all of these must pass:

| # | Check | Pass criterion |
|---|---|---|
| 1 | `pnpm install` (from repo root) | Clean install; no peer-dep errors blocking the install |
| 2 | `pnpm --filter frontend run dev` | Next.js starts on `:3000`; user verifies a page loads in browser |
| 3 | `pnpm --filter frontend run build` | Production build succeeds with same warning profile as before the move |
| 4 | `pnpm --filter frontend run lint` | ESLint output matches pre-move output |
| 5 | `pnpm turbo run typecheck` | `tsc --noEmit` clean |
| 6 | `git log --follow apps/frontend/lib/prisma.ts` | Rename history preserved |
| 7 | Spot-check: open the dashboard or P&L page | Loads without error |

If any check fails, the PR doesn't open — fix on the branch first.

## Section 5 — Risks & rollback

| Risk | Likelihood | Mitigation |
|---|---|---|
| Existing `apps/frontend/tsconfig.json` already has its own `extends` (e.g. `next/core-web-vitals`) and conflicts with extending `tsconfig.base.json` | Medium | Inspect during implementation; either extend the base from `next/core-web-vitals` chain or merge settings inline. The implementation plan must read the file first before editing. |
| Some absolute import path resolves wrong after move | Low | tsconfig `@/*` alias is relative to `apps/frontend/`; survives the move with no edits |
| pnpm hoisting breaks shadcn/Radix peer-dep resolution | Medium | `.npmrc` includes `public-hoist-pattern[]=*radix*` and `*tailwind*` as a precaution |
| Prisma client regen breaks | Low | `postinstall: prisma generate` is a relative-path script; pnpm runs it per workspace |
| `.env` not picked up under new path | Very low | Next.js auto-reads `.env*` from project root (= `apps/frontend/`) |
| `sync-ads-cron.yml` breaks | None | Only curls a deployed URL; repo-path-independent |
| Mid-move regret about scope | Low | Same branch can absorb additional commits; nothing is irreversible until merge |
| Catastrophic: undo whole thing | Very low | `git revert <merge-commit>` on main; all `git mv` operations reverse cleanly |

## Open questions / explicit non-decisions

- **Workspace package naming convention** — deferred. Frontend keeps `shopify-analitcs`. When `packages/*` come online (Phase 1+), choose `@brain/*` namespace or `@looqus/*` then.
- **Turborepo remote cache** — deferred. Add when CI wall time becomes painful or when more than one workspace is buildable.
- **`pnpm` version pinning via `packageManager` field** — included in root `package.json` to keep contributors aligned. Pin to current stable (e.g. `pnpm@9.x`).
